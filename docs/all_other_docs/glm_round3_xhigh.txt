## (3) `sign_product == 0` Edge Case

- `sign_product > 0` → same hemisphere → parallel
- `sign_product < 0` → opposite hemisphere → contraparallel
- `sign_product == 0` → **one or both declinations are exactly 0°**

- `dec1 = 0.0, dec2 = +1.0` → `|dec1 - dec2| = 1.0` AND `|dec1 + dec2| = 1.0` — **both parallel and contraparallel distances are identical**. The hemisphere test is ambiguous.
- `dec1 = 0.0, dec2 = 0.0` → both at equator. Same point. Should be parallel (identical declination).

If the code uses strict `> 0` / `< 0` branching, `sign_product == 0` falls through to neither branch, producing **zero output for a real configuration**. This is a silent zero, not a NaN — worse, because it looks like "no aspect" when there might be one.

**Fix:**
```python

    # Same hemisphere → parallel
    parallel_dist = abs(dec1 - dec2)
    contraparallel_dist = float('inf')
elif dec1 * dec2 < 0:
    # Opposite hemisphere → contraparallel
    parallel_dist = float('inf')
    contraparallel_dist = abs(dec1 + dec2)
else:
    # Edge case: at least one declination is exactly 0°
    # Convention: treat 0° as belonging to both hemispheres.
    # Compute both distances and take the minimum as the active aspect.
    parallel_dist = abs(dec1 - dec2)
    contraparallel_dist = abs(dec1 + dec2)
    # When one is 0°, both distances are equal. Assign to parallel
    # (convention: 0° is "north" by default, same-hemisphere with anything ≥0).
    contraparallel_dist = float('inf')  # override: don't double-count
```

**Severity: Medium.** Equator crossings are common events. Silent zeros in feature vectors will confuse any downstream model.

## (4) Does Vaidhriti Have a Secondary 180° Trigger?

Sun's declination ≈ ε × sin(longitude). So:
- Longitude 0°–180° → declination ≥ 0° (north hemisphere)
- Longitude 180°–360° → declination ≤ 0° (south hemisphere)

For `Sun_long + Moon_long = 180°`:
- If both are in 0°–180° → both north → **same hemisphere**
- If both are in 180°–360° → sum = 360°–540°, so sum=180° requires sum≡180° mod 360°, i.e., sum=540° → both south → **same hemisphere**
- If one is in 0°–180° and other in 180°–360° → sum is 180°–540°. For sum=180°, the second would need to be <0° (impossible). For sum=540°≡180°, the first would need to be >180° (impossible).

**Sum=180° always produces same hemisphere for the Sun.** The only way to get opposite hemispheres at sum=180° is if the Moon's ~5° ecliptic latitude wobble pushes its declination across the equator despite its longitude being in the "wrong" half. This is rare and marginal.

The classical Vyatipata at sum=180° is actually **same hemisphere** (both north or both south), not opposite. The code's docstring has the hemisphere rule backwards for the 180° case.

**What the classical texts actually say:**
- **Vyatipata**: Sum = 180° (both in same ayana but opposite to the "natural" configuration) — the "pathological" case. The 360° trigger with opposite hemispheres is the other Vyatipata case.
- **Vaidhriti**: Sum = 0°/360° with same hemisphere. **No 180° trigger.** This is correct in the code.

**The asymmetry (Vyatipata has 2 triggers, Vaidhriti has 1) is classically correct.** But the hemisphere assignment in the docstring is wrong for the 180° Vyatipata case.
